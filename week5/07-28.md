## 작업 과정에서 어려웠던 점 & 배운 점
### 배차 동시성 제어 방안 확정하기
퀵서비스 배달 플랫폼의 핵심 난제 중 하나인, 배차 동시성 제어 방안을 오늘에서야 확정하여 Wiki로 작성할 수 있었다.

Discussion뿐만 아니라 구두로도 활발하게 의견을 나눈 결과, 약 일주일 가량이 소요되었고, 진행 과정은 다음과 같았다.
1. 배차 동시성 제어 주 담당 2명이서 가능한 방안, 방안별 동작방식 및 장단점 등을 조사하여 Discussion에 게재하였다.
2. 각자 조사한 방안 중 최선책을 골라 상대방과 대조한 후, 일차적인 채택안을 선정했다.  
3. 이후 일차적인 채택안에 대해서 팀원들이 코멘트를 달아주었다.
4. 코멘트에서 얻은 인사이트를 기반으로, 최초에 조사했던 방안들을 더욱 깊게 조사하였다.
5. 최종적으로 채택안을 선정하고, 그간의(1~4번) 과정에서 나왔던 내용들을 Wiki로 작성하며 마무리하였다.

과정 자체가 특별하진 않았지만, 모두가 주도적으로 참여해 준 점이 좋았던 것 같다. 가령,
- 담당자들은 7개 가량 되는 선택지들의 동작방식 및 장단점을 꼼꼼히 조사하고, 유효한 선택지의 경우에는 애플리케이션 레벨에서의 코드 전개 방식까지 기술
- 리뷰어들은 다양한 관점에서 선택안을 바라 보고, 관련하여 코멘트 작성

특히 예상 트래픽량을 고민해 봐야 한다든가, 꼭 7가지 중 하나가 아니라 여러 방안의 조합을 고려해보면 좋겠다는 피드백이 기억에 남았다.

다른 측면을 신경쓰다가 고려하지 못했는데, 새로운 시각으로 리뷰어가 봐주니까 놓치고 있던 점을 보완할 수 있었기 때문이다.

담당자뿐만 아니라 리뷰어의 역할 또한 중요하다는 사실을 새삼 깨달을 수 있는 경험이었다.

  - 우선순위는 높지만, 당장 깊이 있게 보지도 않아도 되는 산출물

# 3. 학습 내용
## S3 (Simple Storage Service)
정적 웹 자원(HTML, CSS, JS, 이미지 등)을 보관하는 객체 스토리지다.

### 객체 스토리지 구조
- **버킷 (Bucket):** 
  - 데이터를 저장하는 최상위 컨테이너다. 
  - AWS의 전체 글로벌 리전에서 유일무이한(Unique) 이름을 가져야 한다. 
- **객체 (Object):** 
  - S3에 저장되는 기본 단위다. 파일 데이터 자체, 파일을 설명하는 메타데이터, 그리고 파일을 식별하는 고유한 키(URL 경로)로 구성된다. 
- 일반적인 운영체제처럼 계층형 폴더 구조를 가지는 것이 아니라, 키를 기반으로 평면적(Flat)으로 데이터를 저장하고 검색한다.
  - 단, 콘솔 화면에서는 사용자 편의를 위해 폴더처럼 보이게 시각화해 준다.

### 주요 특징 및 기능
- **정적 웹 호스팅:** 
  - 서버(EC2)를 띄우지 않아도 S3 버킷의 설정만 켜면 HTML, CSS, JavaScript, 이미지 파일 등을 클라이언트에게 직접 제공하는 가벼운 웹 서버 역할을 수행할 수 있다. 
- **무한한 확장성과 내구성:** 
  - 데이터 용량에 제한이 없으며 트래픽 급증에도 자동으로 확장된다. 
  - 또한 여러 시설에 데이터를 분산 복제하여 99.999999999%(11개의 9)라는 극단적인 데이터 내구성을 보장한다. 
- **스토리지 클래스:** 
  - 데이터 접근 빈도에 따라 요금을 최적화할 수 있다. 
  - 자주 쓰는 데이터는 'Standard'에, 가끔 쓰는 백업 데이터는 요금이 저렴한 'Glacier'로 옮기는 식의 수명 주기(Lifecycle) 관리가 가능하다.

## CloudFront
전 세계 엣지 로케이션을 활용해 정적 콘텐츠를 캐싱하고 캐시된 파일 데이터를 고속으로 배포하는 CDN(Content Delivery Network) 서비스다.

### CDN과 엣지 로케이션의 역할
- **개념:** 
  - AWS의 글로벌 콘텐츠 전송 네트워크(CDN) 서비스다. 
- **동작 원리:** 
  - 사용자가 데이터를 요청하면, 원본 서버(Origin - S3 버킷이나 EC2 등)까지 트래픽이 가기 전에 사용자와 가장 가까운 '엣지 로케이션(Edge Location)'에서 요청을 가로챈다. 
- **프록시 캐싱 (Proxy Caching):** 
  - 이 과정에서 프록시 캐싱이 발생한다. 
  - 이는 단순히 지리적으로 멀리 떨어진 해외 호스팅 파일의 전송 속도를 높이는 것에 국한되지 않는다. 
  - 국내 환경이더라도 트래픽이 집중되는 대중적이고 인기 있는 콘텐츠 자원 전반에 대해 캐시를 적용하여 응답 속도를 가속화하고, 백엔드 원본 서버의 부하를 크게 줄여준다.

### 주요 기능 및 보안 활용
- **HTTPS 통신 지원 (SSL/TLS):** 
  - S3의 정적 웹 호스팅 기능 자체는 기본적으로 HTTP 통신만 지원한다. 
  - 커스텀 도메인(예: my-domain.com)에 HTTPS를 적용하려면 반드시 CloudFront를 앞에 배치하고 AWS Certificate Manager(ACM)의 무료 인증서를 연결해야 한다.
- **보안 계층 추가 (WAF):** 
  - AWS WAF(웹 방화벽)를 CloudFront에 연결하여 악의적인 디도스(DDoS) 공격이나 SQL 인젝션 등을 엣지 로케이션 단계에서 원천 차단할 수 있다.
- **OAC (Origin Access Control):** 
  - 외부 사용자가 S3의 URL로 직접 접근하여 콘텐츠를 탈취하지 못하도록 S3의 퍼블릭 접근을 막고, 오직 CloudFront를 통해서만 S3 데이터를 읽을 수 있도록 접근 권한을 철저히 제어할 수 있다.

앞으로의 프로젝트에서도, 팀원의 성향에 맞춰 균형을 조절하는 것을 목표로 노력해야겠다.

# 3. 학습 내용
## 웹 스토리지 (로컬 스토리지 / 세션 스토리지)
둘 다 브라우저가 제공하는 Web Storage API로, 문자열 key-value 쌍을 저장한다는 점은 같지만 데이터가 살아있는 범위가 다르다.

### 로컬 스토리지 (localStorage)
- **개념:** 
  - 브라우저에 origin(프로토콜 + 도메인 + 포트) 단위로 데이터를 저장하는 저장소다. 
  - 만료 기한이 없어서 명시적으로 지우기 전까지 계속 남아있다.
- **특징:** 
  - 탭이나 창을 닫아도, 브라우저를 껐다 켜도 데이터가 유지된다. 
  - 같은 origin이면 여러 탭에서 공유된다.
- **용도:** 
  - 로그인 유지 힌트, 테마 설정, 자주 안 바뀌는 사용자 설정 캐싱 등에 쓴다.

### 세션 스토리지 (sessionStorage)
- **개념:** 
  - 브라우저 탭(세션) 단위로 데이터를 저장하는 저장소다.
- **특징:** 
  - 그 탭을 닫으면 데이터가 사라진다. 
  - 같은 페이지를 새 탭에서 열어도 별도의 세션 스토리지를 가지므로 탭끼리 공유되지 않는다. 
  - 다만 새로고침에는 유지된다.
- **용도:** 
  - 그 탭 안에서만 유효해야 하는 임시 상태 등 탭별로 분리되어야 하는 값에 쓴다.

### 공통점
- **저장 형식:** 
  - 문자열 key-value만 저장할 수 있다. 
  - 객체를 넣으려면 `JSON.stringify`로 직렬화해야 한다.
- **용량 제한:** 
  - 보통 5MB에서 10MB 사이로, 브라우저마다 조금씩 다르다.
- **동기 API:** 
  - 읽고 쓰는 게 동기적으로 처리되기 때문에, 큰 데이터를 자주 다루면 메인 스레드를 블로킹할 수 있다.
- **서버로 자동 전송되지 않는다:** 
  - 쿠키와 다른 점이다. 
  - 쿠키는 매 요청마다 자동으로 서버에 실려가지만, 웹 스토리지의 값은 JS가 명시적으로 보내지 않는 이상 서버로 안 간다.
- **XSS에 취약하다:** 
  - JS 코드로 직접 읽고 쓸 수 있어서, 페이지에 악성 스크립트가 삽입되면 그대로 탈취당할 수 있다. 
  - 쿠키는 `HttpOnly` 옵션으로 JS 접근 자체를 막을 수 있지만, 웹 스토리지에는 그런 옵션이 없다.

## 스왑 메모리 (Swap Memory)
- **개념:** 
  - 물리 메모리(RAM)가 부족할 때, 디스크의 일부 공간을 마치 메모리처럼 사용하는 기법이다.
- **동작:** 
  - OS가 당장 안 쓰는 메모리 페이지를 디스크의 스왑 영역으로 옮기고(swap-out), 그 자리를 다른 프로세스가 쓰게 한다. 
  - 나중에 그 페이지가 다시 필요해지면 디스크에서 다시 읽어온다(swap-in).
- **특징:** 
  - 디스크는 RAM보다 훨씬 느리기 때문에, 스왑이 자주 일어나면 성능이 급격히 나빠진다. 
  - 스왑 아웃/인이 계속 반복되면서 시스템이 거의 일을 못 하는 상태를 스래싱(thrashing)이라고 부른다.
- **용도:** 
  - 물리 메모리가 순간적으로 부족해질 때 프로세스가 강제로 죽는(OOM Kill) 걸 막아주는 안전장치 역할을 한다.
- **주의:** 
  - 스왑은 메모리 부족을 근본적으로 해결하는 게 아니라, 버틸 시간을 벌어주는 정도다. 
  - 스왑이 상시로 많이 발생한다면 인스턴스 사양을 늘리거나 메모리 사용량 자체를 줄여야 한다는 신호로 봐야 한다.

# 1. 작업 회고
## 당일 수행 작업 목록
### 해커톤
- 부스 운영

## 작업 과정에서 어려웠던 점 & 배운 점
### 자체/임직원 피드백
어제와 마찬가지로 현대자동차 본사에서 해커톤 부스를 운영했다.

어제보다 훨씬 많은 임직원 분들께서 방문해 주셨는데, 하루 해 본 덕분일까 오늘은 그들의 반응에 집중할 수 있었다.

기획 팀원들의 설명만으로 충분한 순간도 있었고, 기존의 설명만으로는 명쾌히 전달되지 않는다고 느낀 순간도 있었다. 

하루 내내 '어떻게 설명드리는게 좋을까'를 팀원들과 논의하며 점진적으로 개선해 나간 덕분인지, 어제 대비 굉장히 많은 표를 받을 수 있어서 뿌듯했다. 특히 '서비스가 굉장히 실용적인데, 출시 계획이 있는지?'라는 말씀을 많이 해주셨는데, 그 순간들이 가장 기억에 남는 것 같다.

또한, 격려의 말씀 이외에도 실제 서비스 관점에서 고려되면 좋을 부분들에 대한 피드백을 제공해주시기도 하였다. 가령,
- 특정 통화는 지금 하나의 환율 값(정산 방 생성 시점이든, 직접 입력한 환율이든)으로만 계산되는데, 여행 중에 현금으로 결제한 경우는 그 날의 환율로 적용될 수 있으면 좋을 것 같다.
- 그룹에 결제 내역을 할당하는 것이 아니라, 결제 내역을 선택할 때 해당 결제에 참여할 인원을 선택할 수 있으면 좋을 것 같다.
- ...

특히 환율 정책에 대한 고민이 부족했다는 생각도 들었다. 가령,
- 사는 시점의 환율인지, 파는 시점의 환율인지
- 소수점 어느 자리까지 고려할 것인지
- 서비스 사용자 수가 많아져서, 다루는 금액이 커지게 되는 경우

단순 해커톤이 아니라 실제 서비스라고 가정했을 때, 어떤 영역까지 고려해야 하는지에 대해 고민해 볼 수 있었다.

# 2. 종합 회고
## 잘한 점
### 감사 인사 전하기
- 5일간의 해커톤이 무사히 마무리되었다.
- 해커톤을 즐길 수 있었으면 좋겠다는 소망이 있었는데, 충분히 달성한 것 같아 만족스러운 해커톤이었다.
- 서로가 많이 배려해 준 덕분일까, 해커톤 기간 내내 야근하긴 했지만 그 과정이 결코 괴롭거나 하지 않았다.
  - 2일차에는 어떻게든 개발을 시작할 수 있도록 기획 팀원들이 1일차에 기획을 마무리해주셨다.
  - 기획 업무는 끝난 상황이라 퇴근하셔도 됐음에도 불구하고, 끝까지 남아주시기도 했다.
  - 다른 개발 팀원들도 본인이 맡은 역할 이상으로 해줘서, 팀 산출물을 검토하거나 QA에 몰입할 시간을 확보할 수 있었다.
- 개발 기간뿐만 아니라, 부스 기간에도 협업이 잘 되었다고 느낀 순간이 많았다.
  - 기획 팀원들은 하루 종일 서 있어서 힘들었을 텐데도, 지친 내색 없이 열심히 프로젝트를 소개해 주셨다.
  - 개발 팀원들도 담당 파트에 대해 적극적으로 답변하고, 현장에서 서로의 답변을 보완해 주거나 끝나고 피드백해주기도 하였다.
  - 프로젝트 외적으로도 방문증을 같이 찾는다든가, 화면 연결이 끊겼을 때 대처하는 상황이라든가, 교대로 식사하는 상황에서도 서로 간의 배려를 엿 볼 수 있었다.
- 모두가 비슷한 감정을 느꼈기 때문일까, 해커톤이 끝나고 자연스럽게 서로 감사 인사를 전하는 시간을 가질 수 있었다.
- 기간 대비 작업해야 하는 양이 많은 상황이라 여러모로 걱정했는데, 팀원들 모두에게 좋은 경험으로 남은 것 같아 다행이라는 생각이 든다.

## 아쉬웠던 점
### 자료 유실
- 점심식사 이후 클로드를 확인해보니, 모든 대화 내역이 소실되어 있었다.
- 적어도 해커톤 기간이 끝나고 팀 워크스페이스가 비활성화될 줄 알았는데, 너무 안일하게 생각했던 것 같다.

## 개선할 점
### 주기적으로 백업하기
- 비활성화되자마자 운영진 분께 상황을 설명드렸지만, 데이터를 복원해줄 수 있는 방법이 없다고 하셨다.
- 두 가지 중 하나만 했더라도, 데이터를 보존할 수 있었을텐데 그러지 못해 아쉽다고 생각했다.
  - 비활성화 일정에 대해 미리 문의드리기
  - 주기적으로 데이터를 백업하기
- 미리 문의를 드려 일정을 파악해 두면 좋겠지만 매번 그럴 수는 없으니까, 데이터를 주기적으로 백업하는 습관을 들이도록 하자.
